# waha-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted, read-only MCP server that exposes a WAHA (GOWS engine) instance's WhatsApp groups as structured data, metrics and media, behind an embedded OAuth 2.1 login with the WAHA API key.

**Architecture:** Hono HTTP app serving three surfaces: OAuth endpoints, the MCP endpoint (`createMcpHandler`, stateless, one `McpServer` per request, as in `bsale-mcp`), and a signed media route. Domain/application/infrastructure layout mirrors `~/bsale-mcp`. WAHA is reached through a `WahaGateway` port; raw GOWS payloads are converted to `NormalizedMessage` by a per-engine mapper; metrics are pure functions.

**Tech Stack:** Node >= 24, TypeScript (NodeNext, strict), pnpm, `@modelcontextprotocol/server` ^2 + `@modelcontextprotocol/hono` ^2, `hono` ^4, `@hono/node-server` ^2, `zod` ^4, `node:sqlite` (built-in), Vitest ^5, Biome ^2. Dev: `@modelcontextprotocol/client` ^2, `tsx`.

**Spec:** `docs/superpowers/specs/2026-10-30-waha-mcp-design.md`

## Global Constraints

- Every tool is read-only: registered with `annotations: { readOnlyHint: true }`; no code path calls a WAHA send/edit/delete endpoint.
- `WAHA_API_KEY` and `WAHA_API_URL` never appear in tool output, HTTP responses, error messages or logs.
- Config env vars (names exact): `WAHA_API_URL`, `WAHA_API_KEY`, `WAHA_SESSION` (default `default`), `PUBLIC_BASE_URL`, `DATA_DIR` (default `/data`), `PORT` (default `3000`), `TIMEZONE` (IANA, default `UTC`), `STATS_MAX_MESSAGES` (default `5000`).
- Additional builder-chosen env vars (this plan): `MEDIA_LINK_TTL_SECONDS` (default `600`), `MEDIA_INLINE_MAX_BYTES` (default `5242880`).
- PKCE: `S256` only. Login accepts only the exact `WAHA_API_KEY` (constant-time compare, `crypto.timingSafeEqual` over SHA-256 digests). Login is rate-limited.
- Tokens are opaque random strings (32 bytes, base64url); only their SHA-256 hash is stored. Logout revokes all tokens and clients, effective on the next request.
- GOWS is the only supported engine in v1; any other engine yields `UnsupportedEngineError` with an explicit message, never a silent mis-parse.
- Committed fixtures are scrubbed of phone numbers, names and message text.
- Artifacts (code, comments, README) in English. License MIT. Conventional commits, no AI attribution trailers.
- `config.ts` is pure; `main.ts` is the only file reading `process.env` (bsale-mcp convention).

## Amendment A2 — premium package (2026-10-30, owner: "Dale con todo")

Spec §7.2 "Premium package" is binding. New tasks run after Task 8 and BEFORE Task 9 (so Task 9's
README and smoke test cover all 12 tools and 3 prompts). Shared rules for Tasks 10-13:

- Every new tool: `readOnlyHint: true`, `structuredContent` with an outputSchema, a text summary,
  errors through `defineTool`'s mapping. Reuse the existing gateway, mapper, `fetchRange`, cursor
  and `computeChatStats` — never re-implement message fetching or normalization.
- Owner identity: gateway gains `getMe(): Promise<{ id: string; lid: string | null }>` from
  `GET /api/sessions/{session}/me` (fallback: `me` field of `GET /api/sessions/{session}`), cached
  per process; used to detect mentions of the owner and replies to the owner (`fromMe`).
- Multi-chat fan-out (pending, digest, search, files): candidates come from `gw.listChats`
  filtered by `conversationTimestamp` within the range; at most 5 concurrent per-chat fetches;
  at most `MAX_CHATS_PER_CALL = 100` chats per call; per-chat messages capped by
  `STATS_MAX_MESSAGES`; every result carries a `coverage` block (chats scanned, chats skipped,
  truncated) so the model never assumes completeness. A chat whose fetch fails is listed under
  `coverage.failedChats`, not fatal.
- `scope`: `"direct" | "groups" | "all"`, default `"direct"`. Group pending rule per spec.
- Compact message shape for multi-chat results: `{ id, at, from: "me" | name|phone, type, text
  (≤ 280 chars, "…" when cut), hasAttachment }`.

## Review Focus

1. **A group with no stored history** (GOWS `storage.messages` disabled, or a group joined today): `get_messages`/`get_group_stats` must say history is unavailable/empty-with-coverage, not report "0 messages" as if the group were silent. → Task 5 test `stats coverage reports empty range explicitly`.
2. **Authors who left the group or have no push name**: messages still attribute to the phone/JID; stats count them; silent-member list only uses current participants. → Task 4 and Task 5 tests.
3. **Media deleted/expired on WAHA**: `get_media` returns a normal result saying the file is no longer available, never `isError`. → Task 8 test `get_media reports unavailable media`.
4. **Token used after logout or expiry**: `/mcp` answers 401 with `WWW-Authenticate: Bearer resource_metadata="…"` so the client re-runs OAuth. → Task 7 test.
5. **Very large image/sticker**: above `MEDIA_INLINE_MAX_BYTES` it is returned as a signed link, not inlined. → Task 8 test.
