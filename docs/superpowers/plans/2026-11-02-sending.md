# Sending messages and attachments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner's MCP clients send WhatsApp text, attachments, locations and contact cards through WAHA, with WhatsApp-correct formatting and attachments uploaded outside the model.

**Architecture:** A new `WhatsAppSender` port (POST-only) sits beside the read-only `WahaGateway` and is implemented by `WahaHttpSender`. Files reach the server through signed one-time `/upload/:token` links into a filesystem `UploadStore`; the server forwards them to WAHA as base64. A pure `toWhatsAppText` normalizer runs on every text and caption. Five new tools use per-tool MCP annotations.

**Tech Stack:** Node 24, TypeScript, Hono, `@modelcontextprotocol/server` v2, zod 4, vitest, biome, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-02-sending-design.md`

## Global Constraints

- No new runtime dependencies.
- No env toggle for sending: the tools are always registered.
- Requires WAHA ≥ 2026.6.1 (or Plus) for media; older WAHA → "This WAHA does not support sending media; update to 2026.6.1 or later."
- Upload TTL default 900 s (`UPLOAD_TTL_SECONDS`), size cap default 64 MB = 67108864 bytes (`UPLOAD_MAX_BYTES`).
- Upload links are single use; the stored file is deleted only after WAHA confirms the send.
- No automatic retries of any send.
- Every send tool and `create_upload_link`: annotations `{ readOnlyHint: false, destructiveHint: false, idempotentHint: false, openWorldHint: true }`. Read tools keep `{ readOnlyHint: true }`.
- WAHA POSTs: `redirect: "error"`, `X-Api-Key` header, error messages never contain the key or base URL.
- Artifacts (code, comments, docs, commits) in English. Conventional commits, no AI attribution lines.
- Work on branch `feat/send-messages`. Run `pnpm typecheck && pnpm lint && pnpm test` before each commit.

## Review Focus

1. Retrying `send_media` with an `upload_id` that was already sent → clear "already sent or expired; create a new upload link" error, no crash, nothing sent (Task 6).
2. Accents, ñ and emoji in text and filenames (`Cotización Ñandú 🎉.pdf`) → bytes and names reach WAHA unchanged (Tasks 1, 4).
3. `curl -T` uploads arrive without a useful Content-Type → mimetype falls back to the filename extension (Task 4).
4. Server restart between `create_upload_link` and the upload/send → the slot still works because metadata lives on disk (Task 3).
5. Text longer than WhatsApp's 65536-character limit → `InvalidInputError` before calling WAHA (Task 5).

**Interfaces:**
- Produces:
```ts
export interface UploadSlot { id: string; filename: string; mimetype: string | null; size: number | null; expiresAt: number; uploaded: boolean }
export type WriteResult = "ok" | "too_large" | "already_uploaded" | "not_found";
export interface UploadStore {
  create(q: { filename: string; mimetype: string | null }): UploadSlot;
  get(id: string): UploadSlot | null;              // null when unknown or expired
  write(id: string, body: ReadableStream<Uint8Array>, contentType: string | null): Promise<WriteResult>;
  read(id: string): Promise<OutgoingFile | null>;  // null unless uploaded and not expired
  remove(id: string): void;
  sweep(): number;                                 // deletes expired slots, returns count
}
export function createFsUploadStore(opts: { dir: string; ttlSeconds: number; maxBytes: number; now?: () => number }): UploadStore;
export function createUploadLinks(mediaSecret: Uint8Array, ttlSeconds: number): SignedLinks; // key = HMAC-SHA256(mediaSecret, "upload")
```
- `Config` gains `uploadMaxBytes` (`UPLOAD_MAX_BYTES`, default 67108864) and `uploadTtlSeconds` (`UPLOAD_TTL_SECONDS`, default 900), parsed with the existing `positiveInt`.
- Mimetype precedence on `write`/`read`: slot mimetype (from the tool) > upload Content-Type (ignored when `application/octet-stream` or absent) > extension of filename via `mimetypeFromFilename(name: string): string` (exported from `fsUploadStore.ts`; jpg/jpeg/png/webp/gif/mp4/mov/ogg/opus/mp3/m4a/pdf/docx/xlsx/pptx/zip/txt/csv, else `application/octet-stream`).
