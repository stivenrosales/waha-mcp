# Self-Hosted Install — Design

Date: 2026-11-21. Status: approved by the owner (project C of the three agreed on 2026-11-21).

## Intent

Someone, or their AI agent (Claude Code), should be able to install waha-mcp on a VPS (the
primary target) or on a laptop with a handful of commands: one `docker compose up` that runs
WAHA (GOWS) and waha-mcp together, secrets generated by a script, WhatsApp paired from a QR,
and the MCP connected to Claude. A fresh install serves one person, the owner; inviting other
people stays possible but has to be turned on.

## Goals

- `docker-compose.yml` at the repository root: `waha` (GOWS engine) and `waha-mcp` (built from
  the existing `Dockerfile`), named volumes for WAHA's sessions and media and for waha-mcp's
  `DATA_DIR`, healthchecks on both, and an optional `caddy` service (compose profile `https`)
  that terminates HTTPS for a VPS domain.
- Config through an env file copied from `compose.env.example`; `scripts/init-env.sh` writes
  `.env` with every secret generated (`MASTER_KEY`, `ADMIN_PASSWORD`, `WAHA_API_KEY`,
  `WAHA_WEBHOOK_SECRET`, WAHA dashboard password), mode 600, never printing them.
- Single owner by default: a new `MULTI_TENANT` variable. Off, the admin keeps the usage tools
  (`get_tool_usage`, `get_transcription_usage`, `get_llm_usage`) but not the tenant-management
  tools (`list_tenants`, `create_invite`, `reset_password`, `revoke_tenant`, `restore_tenant`,
  `delete_tenant`), the admin instructions do not mention them, and `/invite/:token` answers 404.
- `AGENTS.md` (agent runbook, end to end), `docs/self-hosting.md` (humans), a README section.
- `docker compose config` validates the file; images are not pulled and nothing is started.

## Non-goals

- Publishing a waha-mcp image to a registry, Kubernetes, one-click marketplace templates.
- Pairing the owner's WhatsApp through waha-mcp's `/pair` page (it is reached only with the
  invite cookie). The owner pairs through WAHA: the QR printed in `docker compose logs waha`,
  WAHA's dashboard over an SSH tunnel, or the QR PNG fetched with curl.
- Changing what multi-tenant does once it is on.

## Anti-goals

- An upgrade silently removes `create_invite` from a server that already has members.
- WAHA reachable from the internet in the default compose file.
- A secret printed to the terminal or committed.

## Design

### `MULTI_TENANT`

- Parsed like `ADMIN_PASSWORD_RESET` (`1`/`true`/`0`/`false`, case-insensitive), but tri-state:
  unset or empty is "auto". `Config.multiTenant: boolean | null`. An invalid value is a startup
  error: `MULTI_TENANT must be "1", "true", "0" or "false".`
- Resolved once in `composeApp` (startup): `config.multiTenant ?? (tenants.listTenants().length > 1)`.
  Auto therefore keeps an existing multi-tenant deployment (any tenant besides the admin's,
  including a pending invite) in multi-tenant mode, and makes a fresh install single-owner.
  `ComposedApp.multiTenant` exposes the result; `main.ts` adds `mode: single-owner|multi-tenant`
  to the startup log line.
- Single-owner: `createMcpServer` gets the usage tools only (`createUsageTools()`, which
  `createAdminTools()` now builds on) and `OWNER_INSTRUCTIONS` instead of `ADMIN_INSTRUCTIONS`.
  The onboarding routes get `invites: false`: `GET` and `POST /invite/:token` answer the
  existing 404 "Enlace no válido" page. `/reset/:token` and `/pair` are unchanged (no link can
  be issued without the hidden tools; existing members keep working when the operator forces
  `MULTI_TENANT=false`).

### Compose stack

- `waha`: `${WAHA_IMAGE:-devlikeapro/waha:gows}`, `WHATSAPP_DEFAULT_ENGINE=GOWS`,
  `WAHA_API_KEY`, dashboard and swagger credentials, `WHATSAPP_START_SESSION=${WAHA_SESSION}`
  (the owner's session exists and starts on every boot), `WAHA_PRINT_QR=True`, volumes on
  `/app/.sessions` and `/app/.media`. Port published only on `127.0.0.1:${WAHA_HOST_PORT:-3001}`.
  Healthcheck: `node` fetching `/ping`.
- `waha-mcp`: `build: .`, `env_file: .env`, `WAHA_API_URL=http://waha:3000` forced,
  `DATA_DIR=/data` on a named volume, published on `${WAHA_MCP_BIND:-127.0.0.1}:${WAHA_MCP_PORT:-3000}`,
  `depends_on: waha (service_healthy)`, `stop_grace_period: 30s`, the image's own healthcheck
  repeated in compose so `docker compose ps` shows it.
- `caddy` (profile `https`): `caddy reverse-proxy --from ${DOMAIN} --to waha-mcp:3000`, ports
  80/443, volumes for its data and config.
- Persistent state: SQLite files under `/data` (auth, tenants, encrypted caches), WAHA sessions
  and media. No database server.

## Assumptions

- Env template name: `compose.env.example` (copied to `.env`). The repository's existing
  `.env.example` (local `pnpm dev`) is left as it is; the stack overrides `WAHA_API_URL`, so the
  same `.env` can drive both.
- `MULTI_TENANT` unset means auto (members already present → multi-tenant), not a hard `false`,
  so upgrading the running multi-tenant deployment changes nothing.
- WAHA image defaults to `devlikeapro/waha:gows` (`gows-arm` on arm64, picked by the init script; `latest` is amd64 only) (GOWS needs WAHA 2026.6.1+ Core for media and
  more than one session); `WAHA_IMAGE` pins a version.
- The owner pairs WhatsApp through WAHA (logs QR, dashboard via SSH tunnel, or curl PNG).
- HTTPS on a VPS through the bundled Caddy profile; a laptop install uses
  `PUBLIC_BASE_URL=http://localhost:3000`, which works with Claude Code but not with claude.ai
  (claude.ai needs a public HTTPS URL).
- `list_tenants` is hidden in single-owner mode (it only lists the owner).
